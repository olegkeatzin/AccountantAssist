# Product Description Generator

Автоматический генератор описаний товаров для Excel файлов с использованием интернет-поиска (DuckDuckGo API) и LLM из Ollama.

## 🚀 Возможности

- Чтение Excel файлов с номенклатурой товаров
- Автоматический поиск информации о товарах в интернете через **DuckDuckGo API**
- Суммаризация найденной информации с помощью LLM (Ollama)
- Добавление нового столбца с расшифровкой названий товаров
- Добавление столбца со ссылками на источники данных
- Поддержка пользовательского хоста Ollama
- Автоматическое сохранение прогресса после каждой обработанной строки
- Подробное логирование процесса

## 📋 Требования

1. **Python 3.12** или выше
2. **Ollama** с установленной моделью (например, llama3.2, gemma3:4b)
3. **uv** (менеджер пакетов) или pip

## 🎯 Использование

### Базовое использование

```powershell
python product_description_generator.py
```

По умолчанию скрипт:
- Читает файл `Номенклатура полная.xlsx`
- Создает файл `Номенклатура полная с описаниями.xlsx`
- Использует колонку "Полное наименование"
- Добавляет колонку "Расшифровка"
- Подключается к Ollama на localhost
- Использует модель llama3.2
- Ищет через DuckDuckGo API

### Параметры командной строки

| Параметр | Описание | По умолчанию |
|----------|----------|------------|
| `--input` | Путь к входному Excel файлу | `Номенклатура полная.xlsx` |
| `--output` | Путь к выходному Excel файлу | `Номенклатура полная с описаниями.xlsx` |
| `--column` | Название колонки с товарами | `Полное наименование` |
| `--description-column` | Название новой колонки | `Расшифровка` |
| `--sources-column` | Название колонки со ссылками | `Источники` |
| `--ollama-host` | Хост Ollama | `http://localhost:11434` |
| `--ollama-model` | Модель Ollama | `llama3.2` |
| `--no-skip-existing` | Перезаписать существующие описания | `false` |
| `--verbose`, `-v` | Подробное логирование | `false` |

### Примеры использования

#### Базовый запуск с другой моделью:

```powershell
python product_description_generator.py --ollama-model "gemma3:4b"
```

#### Подробное логирование:

```powershell
python product_description_generator.py --verbose
```

#### Полный пример:

```powershell
python product_description_generator.py `
  --input "Номенклатура полная.xlsx" `
  --output "Результат.xlsx" `
  --column "Полное наименование" `
  --description-column "Расшифровка" `
  --sources-column "Источники" `
  --ollama-host "http://127.0.0.1:11434" `
  --ollama-model "gemma3:4b" `
  --verbose
```

## 🔄 Как работает скрипт

1. **Проверка возобновления**: При запуске ищет файл `_previous.xlsx` для возобновления работы с последней строки
2. **Чтение Excel файла**: Загружает данные из указанного файла
3. **Копирование прогресса**: Если найден `_previous.xlsx`, копирует все обработанные описания
4. **Фильтрация служебных записей** (пропускаются):
   - Строки с "Вид воспроизводства" = "Производство"
   - Строки с "Вид номенклатуры" ≠ "Товар" (обрабатываются только товары)
   - Строки с "ИСПОЛЬЗОВАТЬ" или "не заполнять, висят док-ты по отгрузке"
5. **Использование комментариев**: Если есть столбец "Комментарий", его содержимое используется как дополнительный контекст для LLM
6. **Поиск в интернете**: 
   - Использует DuckDuckGo API с приоритетом русскоязычных сайтов (регион ru-ru)
   - Исключает Wikipedia и другие wiki-сайты
   - Ищет до 10 результатов для лучшего качества
7. **Извлечение информации**: Парсит найденные веб-страницы и извлекает до 5000 символов текста. Сохраняет ссылки на успешные источники
8. **Суммаризация**: Отправляет найденную информацию и комментарии в Ollama для создания краткого описания
9. **Сохранение**: Добавляет описание в колонку и список ссылок на источники (через запятую с пробелом) и сохраняет файл после каждой строки

### 🔄 Возобновление работы при перезапуске

Скрипт автоматически продолжает работу с места остановки! Подробнее см. [RESUME_INFO.md](RESUME_INFO.md)

## 💡 Режимы работы

Скрипт работает в двух режимах:

### 🌐 С интернет-данными (предпочтительно)
- Находит информацию на веб-страницах
- Создает описание на основе реальных данных
- Более точное и подробное описание

### 🤖 На основе названия (резервный)
- Используется когда информация в интернете не найдена
- LLM анализирует название товара
- Создает описание из своих знаний
- Помечается как `[На основе названия]`

## 📊 Особенности

- ✅ **Автосохранение**: Прогресс сохраняется после каждой строки
- ✅ **Возобновление работы**: При перезапуске скрипт продолжает с последней обработанной строки (на основе `_previous.xlsx`)
- ✅ **Автоматические бэкапы**: Система ротации файлов (текущий + предыдущий)
  - При каждом сохранении создается бэкап предыдущей версии
  - Файл `*_previous.xlsx` всегда содержит последнюю рабочую версию
  - Защита от потери данных при сбоях
  - **НОВОЕ**: Используется для автоматического возобновления работы
- ✅ **Счетчик прогресса**: Показывает текущую позицию и количество оставшихся строк
- ✅ **Пропуск обработанных**: По умолчанию пропускает уже заполненные описания
- ✅ **Фильтрация служебных записей** (просто пропускаются): 
  - "Вид воспроизводства" = "Производство"
  - "Вид номенклатуры" ≠ "Товар" (обрабатываются только товары)
  - Содержит "ИСПОЛЬЗОВАТЬ" или "не заполнять, висят док-ты по отгрузке"
- ✅ **Использование комментариев**: Столбец "Комментарий" добавляется как контекст для LLM
- ✅ **Приоритет русских сайтов**: Поиск настроен на регион ru-ru
- ✅ **Исключение Wikipedia**: Фильтруются все wiki-сайты из результатов
- ✅ **Расширенный поиск**: До 10 результатов вместо стандартных 3
- ✅ **Поддержка товаров и услуг**: Универсальные промпты для обоих типов
- ✅ **Подробное логирование**: Используйте `--verbose` для деталей
- ✅ **Обработка ошибок**: Продолжает работу даже при ошибках
- ✅ **API вместо scraping**: Использует официальную библиотеку DuckDuckGo

## ⚠️ Возможные проблемы

### Ollama не отвечает

```powershell
# Проверьте, что Ollama запущен
ollama list

# Проверьте доступность
curl http://localhost:11434
```

### Информация не найдена

Это **нормально**! Скрипт все равно создаст описание на основе названия товара. Используйте `--verbose` для подробностей.

### Медленная работа

Обработка занимает время (поиск в интернете + работа LLM). Это нормально для качественного результата.

### Файл поврежден или ошибка сохранения

Скрипт создает автоматические бэкапы! Если основной файл поврежден:

```powershell
# Бэкап находится в том же каталоге с суффиксом _previous
# Например, если выходной файл: Результат.xlsx
# То бэкап будет: Результат_previous.xlsx
```

Просто переименуйте `*_previous.xlsx` в нужное имя или скопируйте данные из него.
